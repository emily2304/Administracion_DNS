## 5. Problemas

No se presentaron bloqueos que impidieran continuar el desarrollo durante esta semana.

Durante la validación de infraestructura se comprobó que los cuatro componentes pueden construirse mediante Docker y que DNS Interceptor, DNS API y DNS UI pueden desplegarse correctamente en Kubernetes. También se validó la resolución interna del Service `dns-api` y la conectividad HTTP entre componentes.

La integración funcional completa de los registros `geo` y `round-trip` queda condicionada a que el DNS API y el Health Checker proporcionen los datos reales requeridos. Actualmente el DNS API continúa utilizando datos mock para la consulta de registros y el Health Checker todavía utiliza targets de prueba y no persiste los resultados `healthy/unhealthy` ni las mediciones RTT en Supabase.
